## Цель лабораторной работы №2

Построить слой **DDS** на основе сырых данных из ЛР1 (ODS) и реализовать:

- нормализацию данных (структура хранилища, приведение к 3НФ),
- DAG трансформаций ODS → DDS,
- зависимости между процессами (DDS ждёт завершение ODS),
- подход к SCD (медленно изменяющиеся измерения),
- DAG Data Quality проверок.

## DDS модель (PostgreSQL)

DDS реализован в отдельной БД `dds_manga` (сервис `postgres_dds`) в схеме `dds`.

### Измерения (3НФ / snowflake элементы)

- `dds.dim_title_type(type_id, type_name)`
- `dds.dim_title_status(status_id, status_name)`
- `dds.dim_translate_status(translate_status_id, translate_status_name)`
- `dds.dim_genre(genre_id, genre_name, genre_dir)`

### SCD2 измерение

`dds.dim_title_scd2` — версия сущности “тайтл” во времени:

- `title_id` — бизнес‑ключ,
- `title_sk` — surrogate key,
- `valid_from`, `valid_to`, `is_current` — атрибуты SCD2,
- атрибуты: названия, год, метрики, cover, флаги, ссылки на `type/status/translate_status`.

### Связь many‑to‑many

`dds.bridge_title_genre(title_sk, genre_id)` — связь текущей версии тайтла (SCD2) с жанрами.

### Факты

`dds.fct_top_titles_snapshot` — “снимок топа”:

- ключ: `(batch_ts, period, section, rank)`
- `title_sk` + метрики (rating/views/votes/chapters/bookmarks…).

## DAG’и

### 1) Dimensions DAG

Файл: `dags/remanga_dds_dimensions_postgres.py`  
DAG id: `remanga_dds_dimensions_postgres`

- ждёт готовность ODS через **сенсор SQL** (проверка наличия данных в `ods_remanga_titles_top_pg`)
- создаёт DDS таблицы
- загружает справочники (type/status/translate_status/genre) из `raw`
- загружает `dim_title_scd2` (SCD2) и мост `bridge_title_genre`

### 2) Facts DAG

Файл: `dags/remanga_dds_facts_postgres.py`  
DAG id: `remanga_dds_facts_postgres`

- ждёт готовность измерений через **сенсор SQL** (проверка существования `dds.dim_title_scd2`)
- создаёт fact таблицу
- извлекает строки из ODS через подключение `postgres_ods` и загружает в DDS через `postgres_dds` (ODS и DDS в разных БД)
- вставляет снимок за последнюю выгрузку (idempotent `ON CONFLICT DO NOTHING`)

### 3) Data Quality DAG

Файл: `dags/remanga_dds_data_quality_postgres.py`  
DAG id: `remanga_dds_data_quality_postgres`

Проверки:

- объёмы: минимум 100 строк на `(period, section)` для последнего `batch_ts`
- отсутствие `NULL title_id` в ODS для последнего batch
- диапазон `rating` в \([0,10]\)
- согласованность: `facts >= 0.9 * ods` для последнего batch
